# 할 일 목록 앱 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** localStorage에 저장되는 React + TypeScript 할 일 목록 앱을, 계층 분리와 테스트를 보여주는 포트폴리오 수준으로 만든다.

**Architecture:** 순수 도메인 계층(`domain/`: reducer와 selector)과 영속화 계층(`storage/`)을 커스텀 훅 `useTodos`가 묶고, 표시 전용 컴포넌트는 `App`에서 props로만 데이터를 받는다. 상태는 `useReducer`, 필터는 `App`의 `useState`.

**Tech Stack:** Vite, React 18, TypeScript (strict), Vitest, React Testing Library, `@testing-library/user-event`, jsdom, ESLint, Prettier

**Spec:** `docs/superpowers/specs/2026-11-06-todo-app-design.md`

## Global Constraints

- TypeScript `strict: true`. `any` 사용 금지.
- 외부 상태 관리 라이브러리 금지. `useReducer` + 커스텀 훅만 사용.
- `dangerouslySetInnerHTML` 사용 금지. 제목은 React 텍스트 노드로만 렌더링.
- `domain/`은 React를 import하지 않는다. `storage/`는 `domain/types`만 import한다.
- 저장 키: `ssosso-todos-v1`
- `id`는 `crypto.randomUUID()`, `createdAt`은 `Date.now()`. 둘 다 훅에서 만든다 (reducer 안에서 만들지 않음).
- 화면 문구는 한국어. 남은 개수 문구: `남은 할 일 N개`
- 필터 버튼 문구: `전체`, `진행 중`, `완료`. 일괄 삭제 버튼 문구: `완료 항목 삭제`
- 입력창 placeholder와 `aria-label`: `할 일을 입력하세요`
- 빈 목록 안내 문구: `할 일이 없습니다. 위에 입력해 추가해 보세요.`
- npm 스크립트: `dev`, `build`, `test`, `lint` (`test`는 `vitest run`)

## Review Focus

1. **한글 IME 조합 중 Enter**: 한글을 입력하고 Enter를 누르면 조합 중인 글자 때문에 항목이 두 번 추가되거나 마지막 글자가 따로 추가될 수 있다. `e.nativeEvent.isComposing`이 true이면 Enter를 무시해야 한다. → Task 6 테스트
2. **수정 중 Esc 후 blur**: Esc로 취소하면 입력창이 사라지며 blur가 발생하는데, 이때 blur 저장이 실행되면 취소가 무력화된다. Esc 이후 blur는 저장하지 않아야 한다. → Task 6 테스트
3. **공백만 있는 제목**: `"   "`로 추가하면 무시, 수정하면 삭제. → Task 2, Task 6 테스트
4. **이전 버전이나 다른 앱이 남긴 저장 데이터**: `title`이 숫자이거나 `completed`가 없는 항목은 버리고 나머지는 살린다. → Task 4 테스트
5. **띄어쓰기 없는 아주 긴 제목**: 레이아웃이 가로로 넘치지 않아야 한다 (`overflow-wrap: anywhere`). → Task 6 스타일 + Task 7 수동 확인

### Task 5: useTodos 훅

**Files:**
- Create: `src/hooks/useTodos.ts`
- Test: `src/hooks/useTodos.test.ts`

**Interfaces:**
- Consumes: `todoReducer` (Task 2), `load`, `save`, `STORAGE_KEY` (Task 4)
- Produces:
  ```ts
  function useTodos(): {
    todos: Todo[];
    addTodo(title: string): void;
    toggleTodo(id: string): void;
    editTodo(id: string, title: string): void;
    removeTodo(id: string): void;
    clearCompleted(): void;
  }
  ```

- [ ] **Step 1: 실패하는 테스트 작성** (`renderHook`, `act`):
  - 저장소에 항목 1개를 넣고 렌더링 → `result.current.todos`에 그 항목
  - `addTodo('운동')` → `todos.length === 1`, `title === '운동'`, `id`가 비어 있지 않은 문자열
  - `addTodo` 두 번 → 두 `id`가 서로 다름
  - 변경 후 `JSON.parse(localStorage.getItem(STORAGE_KEY)!)`가 `todos`와 같음
  - 훅을 unmount 후 다시 렌더링 → 이전 항목이 그대로 있음
  - `load`가 처음 렌더링 때 한 번만 불리는지: `vi.spyOn(storage, 'load')` 후 rerender 2회 → 호출 1회
- [ ] **Step 2:** `npx vitest run src/hooks` → FAIL
- [ ] **Step 3:** 구현. `useReducer(todoReducer, undefined, load)`로 지연 초기화. `useEffect(() => save(todos), [todos])`. 액션 함수는 `useCallback`으로 감싸고, `addTodo`에서 `crypto.randomUUID()`와 `Date.now()`를 만들어 액션에 담는다.
- [ ] **Step 4:** → PASS

- Produces (props):

  - `TodoItem({ todo: Todo; onToggle(id): void; onEdit(id, title): void; onRemove(id): void })`
  - `TodoList({ todos: Todo[]; onToggle; onEdit; onRemove })` — 같은 콜백 시그니처
  - `TodoFooter({ activeCount: number; hasCompleted: boolean; filter: Filter; onFilterChange(f: Filter): void; onClearCompleted(): void })`

접근 가능한 이름 (테스트가 이 이름으로 찾는다):
- 입력창: `할 일을 입력하세요`
- 체크박스: `{제목} 완료`
- 삭제 버튼: `{제목} 삭제`
- 수정 입력창: `{제목} 수정`
- 필터 버튼: `전체` / `진행 중` / `완료`, 선택된 버튼은 `aria-pressed="true"`

- [ ] **Step 1: 실패하는 통합 테스트 작성** (`userEvent.setup()`):
  - 입력 `우유 사기{Enter}` → 목록에 `우유 사기`, 입력창은 빈 값, `남은 할 일 1개`
  - 입력 `   {Enter}` → 목록에 항목 없음, 빈 목록 안내 문구 표시
  - 처음 화면(항목 없음) → 빈 목록 안내 문구, 필터 버튼 없음
  - 체크박스 클릭 → `남은 할 일 0개`, `완료 항목 삭제` 버튼 표시
  - 완료 항목이 없을 때 → `완료 항목 삭제` 버튼 없음
  - 필터 `진행 중` → 완료된 항목 숨김, 해당 버튼 `aria-pressed="true"`. 필터 `완료` → 진행 중 항목 숨김
  - `완료 항목 삭제` → 완료 항목 사라짐
  - 삭제 버튼 → 항목 사라짐
  - 제목 더블클릭 → 수정 입력창에 기존 제목. `{Control>}a{/Control}새 제목{Enter}` → `새 제목`으로 바뀜
  - 수정 중 `바뀐 내용{Escape}` → 원래 제목 유지, 이후 다른 곳 클릭(blur)해도 원래 제목 유지 *(Review Focus 2)*
  - 수정 중 다른 곳 클릭(blur) → 저장됨
  - 수정 중 전부 지우고 Enter → 항목 삭제 *(Review Focus 3)*
  - IME: 입력창에 `fireEvent.keyDown(input, { key: 'Enter', isComposing: true })` → 항목 추가되지 않음 *(Review Focus 1)*. 수정 입력창도 같은 검사.
  - `unmount` 후 `<App />` 다시 렌더링 → 항목 유지
  - 키보드만으로: `Tab`으로 체크박스에 포커스 이동 후 `{Space}` → 완료 처리
- [ ] **Step 2:** `npm test` → FAIL
- [ ] **Step 3:** 컴포넌트 구현
  - `TodoInput`: `<form onSubmit>` 대신 `onKeyDown`에서 `key === 'Enter' && !e.nativeEvent.isComposing`일 때만 `onAdd`. 공백 제목 처리는 reducer에 맡기고, 입력창은 항상 비운다.
  - `TodoItem`: `isEditing`과 `draft`는 로컬 state. Esc 처리 시 `cancelledRef.current = true`로 표시하고, `onBlur`는 이 값이 true이면 저장하지 않는다. 수정 시작 시 입력창에 `autoFocus`.
  - `TodoFooter`: `hasCompleted`가 false이면 일괄 삭제 버튼을 렌더링하지 않는다.
- [ ] **Step 4:** `App.tsx`에서 `useTodos`와 `useState<Filter>('all')`을 조립한다. `todos.length === 0`이면 `TodoList`와 `TodoFooter` 대신 안내 문구를 렌더링한다. `App.css`: 최대 너비 560px 가운데 정렬, 좌우 여백 16px, 제목에 `overflow-wrap: anywhere` *(Review Focus 5)*, 완료 항목은 취소선과 흐린 색.
